# Task A: UI/UX pass — implementation plan

> Executed natively in the autonomous run (plan pre-approved). Critique first, then build, then look.

**Goal:** compact grouped controls, a one-handed phone layout, compare mode, plain-language captions on the Quantization tab, and a DF-I signal-flow diagram, with no change to DSP results.
**Spec:** `docs/superpowers/specs/2026-11-19-filterlab-design.md` (Task A details).

## Critique (ui-ux-pro-max searches + impeccable critique, in-thread)
1. Phone: about 1,050 px of controls before the first chart; tabs stranded mid-page. -> collapsible groups; bottom tab bar fixed, body padding to match (ux: "sticky navigation must not obscure content").
2. Desktop controls panel 1,040 px tall, more than a 768 px viewport. -> `<details>` groups; Method and Size collapsed, with their value shown in the summary.
3. Quantization tab gives numbers without interpretation. -> one or two plain sentences per chart.
4. No way to compare two designs. -> Pin as B; dashed, neutral ink, never `#eb6834` (chart: "do not rely on colour alone").
5. The noise model is invisible. -> DF-I diagram with the single rounding point Q and the error-feedback path.
Keep: the honest spec check, tabular numerals, visible focus, legends with data tables.

## Review focus
1. B pinned at another sample rate -> drawn on its own frequency axis; the table and readout leave B out and say why.
2. Fixed tab bar covering the last card or a toast on a phone -> body padding-bottom, toast lifted.
3. Keyboard users and collapsed groups -> native `<details>`/`<summary>` with a visible focus ring.
4. Diagram text unreadable on a phone -> `min-width` plus a local `overflow-x: auto` wrapper.
5. Touch targets -> 44 px minimum on tabs, segments, summaries, inputs and the edge handles' hit area.
